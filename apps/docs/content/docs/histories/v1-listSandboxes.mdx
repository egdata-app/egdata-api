## 2026-11-11 — Keep API startup available while v1 indexes are provisioned separately

Record: [keep-api-startup-independent-of-v1-indexes](https://github.com/egdata-app/egdata-api/blob/main/changes/records/keep-api-startup-independent-of-v1-indexes.json).

- **v1 GET /v1/sandboxes** (listSandboxes; fixed; compatible)
  - Before: GET /v1/sandboxes was unavailable during API startup while v1 MongoDB index creation was pending; the proxy returned 502 before HTTP began listening.
  - After: GET /v1/sandboxes becomes available after the existing database and catalog initialization, without waiting for v1 index provisioning. Its route, authentication, response format and limits are preserved.
  - Client action: None

Verification: tests/server-startup.test.ts: stalled v1 index builds do not delay HTTP startup; database connectivity remains required; pnpm test; pnpm build; pnpm docs:check; pnpm release:check --base origin/main.

## 2026-11-11 — Try v1 operations with ten-minute project console sessions

Record: [project-console-sessions](https://github.com/egdata-app/egdata-api/blob/main/changes/records/project-console-sessions.json).

  - Before: Trying GET /v1/sandboxes in the API Reference required pasting an existing API key secret.
  - After: The project owner can also try GET /v1/sandboxes with a console-only credential lasting at most ten minutes, bound to the same dashboard login. Requests share a stable per-project console quota and count toward project analytics and endpoint alerts. Public API key behavior is preserved.

## 2026-11-11 — Add the versioned v1 API with explicit scopes and per-key quotas

Record: [versioned-v1-api](https://github.com/egdata-app/egdata-api/blob/main/changes/records/versioned-v1-api.json).

- **v1 GET /v1/sandboxes** (listSandboxes; added; compatible)
  - Before: GET /v1/sandboxes was not available in the versioned API.
  - After: List sandboxes. Returns the known Epic namespaces (sandboxes) ordered by namespace identifier (`_id`) ascending. Pass `meta.pagination.nextCursor` as `cursor` to fetch the next page. Response media: application/json. Requires an API key with catalog:read permission; the gateway enforces per-key quotas.
  - Client action: None

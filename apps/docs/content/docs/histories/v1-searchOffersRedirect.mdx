## 2026-11-11 — Keep API startup available while v1 indexes are provisioned separately

Record: [keep-api-startup-independent-of-v1-indexes](https://github.com/egdata-app/egdata-api/blob/main/changes/records/keep-api-startup-independent-of-v1-indexes.json).

- **v1 POST /v1/search** (searchOffersRedirect; fixed; compatible)
  - Before: POST /v1/search was unavailable during API startup while v1 MongoDB index creation was pending; the proxy returned 502 before HTTP began listening.
  - After: POST /v1/search becomes available after the existing database and catalog initialization, without waiting for v1 index provisioning. Its route, authentication, response format and limits are preserved.
  - Client action: None

Verification: tests/server-startup.test.ts: stalled v1 index builds do not delay HTTP startup; database connectivity remains required; pnpm test; pnpm build; pnpm docs:check; pnpm release:check --base origin/main.

## 2026-11-11 — Add the versioned v1 API with explicit scopes and per-key quotas

Record: [versioned-v1-api](https://github.com/egdata-app/egdata-api/blob/main/changes/records/versioned-v1-api.json).

- **v1 POST /v1/search** (searchOffersRedirect; added; compatible)
  - Before: POST /v1/search was not available in the versioned API.
  - After: Normalize search filters to a cacheable GET request. Validates a JSON filter document and returns a bodyless 303 redirect to the equivalent GET URL. No search is executed and no result body is returned. Requires an API key with search:read permission; the gateway enforces per-key quotas.
  - Client action: None

Verification: tests/v1-router.test.ts; tests/v1-operations.test.ts; tests/v1-origin-provenance.test.ts; tests/middleware-origin-auth.test.ts; dashboard/tests/v1-gateway.test.ts; dashboard/tests/rate-limiter.test.ts; pnpm openapi:check.

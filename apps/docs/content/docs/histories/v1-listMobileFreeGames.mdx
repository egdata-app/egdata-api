## 2026-11-12 — Add verified-email onboarding, immutable receipts, privacy operations, and authoritative account closure

Record: [developer-onboarding-account-closure](https://github.com/egdata-app/egdata-api/blob/main/changes/records/developer-onboarding-account-closure.json).

- **v1 GET /v1/free-games/mobile** (listMobileFreeGames; security; breaking)
  - Before: The portal had no self-service account closure or verified-email/terms onboarding. Cached key identity could be used without a fresh account-closure lookup, and active console sessions did not check onboarding.
  - After: Initial publication gates dashboard and console access on verified email followed by explicit terms acceptance. Existing external API keys keep working even after an incomplete dashboard visit. Account closure deletes active credentials and rejects warm/delayed key caches through a primary lookup before quota/cache/upstream access (401 INVALID_API_KEY). Credential/account lookup failure returns uncacheable 503 ACCOUNT_STATUS_UNAVAILABLE with Retry-After: 30; HEAD has no body. Public and configured anonymous bypasses retain their prior behavior. Already-admitted requests may finish; acceptance does not restore revoked keys or reset quotas.
  - Client action: Existing API-key integrations need no onboarding change for this initial rollout. Dashboard/console users must verify a notification email and accept published terms; closure permanently ends their credentials. Retry ACCOUNT_STATUS_UNAVAILABLE after Retry-After; do not automatically retry agreement-related 403 responses.

## 2026-11-12 — Enforce shared 100,000 requests/month allowance across free account projects

Record: [free-account-monthly-quota](https://github.com/egdata-app/egdata-api/blob/main/changes/records/free-account-monthly-quota.json).

- **v1 GET /v1/free-games/mobile** (listMobileFreeGames; changed; breaking)
  - Before: Free projects were governed only by the 120 requests/minute per-project quota and expensive v1 per-operation limits without a monthly account cap, and RateLimit-Policy headers assumed 60-second windows.
  - After: Free accounts share an authoritative 100,000 requests/month allowance across all free projects, API keys, and console sessions across legacy and v1 gateways, resetting on the 1st of each calendar month at 00:00 UTC alongside existing per-project minute and expensive-operation limits. Paid projects (pro, enterprise) are exempt, while custom RPM overrides on free projects retain the monthly cap. Key rotation/deletion and project recreation never reset account usage. Monthly exhaustion returns 429 MONTHLY_QUOTA_EXCEEDED with Retry-After until reset and calendar-aware RateLimit headers; unavailable accounting returns 503 QUOTA_UNAVAILABLE.
  - Client action: Track free-account monthly usage in the developer portal or via RateLimit headers, respect Retry-After until 00:00 UTC on the 1st of next month on 429 MONTHLY_QUOTA_EXCEEDED, or request a Pro/Enterprise tier upgrade in Rate Limits.

Verification: dashboard/tests/monthly-quota.test.ts: simultaneous cap enforcement across keys/projects/console/gateways, calendar and leap-year rollovers, cache hits and upstream 5xx counting, auth/permission/public bypass exclusions, recreation/RPM/tier persistence, dashboard /quota thresholds (80%, 95%, exhausted), and 503 QUOTA_UNAVAILABLE fail-closed handling; dashboard/tests/project-quota.test.ts and dashboard/tests/rate-limiter.test.ts: atomic project minute and expensive-operation admission alongside account monthly policies; src/openapi/project-quota.ts, src/openapi/v1.ts, apps/docs/content/docs/versioned-api.mdx, and dashboard/src/lib/docs/problems.ts; pnpm openapi:generate; pnpm changelog:generate; pnpm docs:check.

## 2026-11-12 — Share gateway quotas across project keys and restrict project creation

Record: [project-shared-quotas](https://github.com/egdata-app/egdata-api/blob/main/changes/records/project-shared-quotas.json).

- **v1 GET /v1/free-games/mobile** (listMobileFreeGames; changed; breaking)
  - Before: Each API key had its own exact minute quota and expensive-operation counters; console sessions had a separate project-console counter. Accounts could create up to ten projects with a non-atomic check.
  - After: All API keys and console sessions in a project share one exact UTC-aligned 60-second global quota across authenticated legacy/v1 gateway traffic, using project tier/custom RPM. Expensive v1 caps are shared per project. Cache hits count; quota exhaustion returns 429 and unavailable admission returns retryable 503 QUOTA_UNAVAILABLE. Legacy responses expose project RateLimit headers. Accounts include one project unless an operator approves more; atomic creation enforces a 24-hour cooldown that survives deletion. Existing projects and keys remain usable.
  - Client action: Keep existing keys; coordinate request budgets across the project's keys, console and API versions. Respect Retry-After and request a project limit increase if necessary. Contact the egdata team for additional projects; creating or rotating keys no longer adds capacity. See docs/project-quota-rollout.md for migration and existing-grant review.
